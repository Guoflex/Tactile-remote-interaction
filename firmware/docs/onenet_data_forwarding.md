# OneNET Data Forwarding

This document explains how Device A sends real-time channel data to Device B through OneNET and a local HTTP forwarding service. All `<...>` values are placeholders.

## Data Flow

```text
Device A
  -> OneNET property reporting
  -> Rule engine
  -> cpolar HTTPS
  -> firmware/tools/onenet_forward_server.py
  -> OneNET device property-setting API
  -> Device B
```

## Thing Model Properties

Device A and Device B use the same properties:

| Property | Type | Description |
| --- | --- | --- |
| `source_id` | string | Source device identifier |
| `frame_id` | integer | Incrementing frame number from Device A |
| `max_tx_idx` | integer | Channel with the maximum value, in the range 0-46 |
| `max_tx_value` | integer | Maximum value after zero calibration |
| `matrix_data` | array | Values of all 47 channels after zero calibration |

## Device A Reporting

Topic:

```text
$sys/<ONENET_PRODUCT_ID>/<ONENET_DEVICE_A_NAME>/thing/property/post
```

Example:

```json
{
  "id": "1",
  "version": "1.0",
  "params": {
    "source_id": { "value": "<ONENET_DEVICE_A_NAME>" },
    "frame_id": { "value": 1 },
    "max_tx_idx": { "value": 46 },
    "max_tx_value": { "value": 218 },
    "matrix_data": { "value": [0, 0, 0] }
  }
}
```

The `matrix_data` example is abbreviated; the actual array always contains 47 values. The device enters the active state when the peak reaches 20 and reports at intervals of at least 100 ms while active. After the value remains at or below 15 for three consecutive frames, it sends a single `{max_tx_idx: 0, max_tx_value: 0}` reset message.

## OneNET Rule

Rule SQL:

```sql
select * from notify where data.params.source_id.value = "<ONENET_DEVICE_A_NAME>"
```

Set the rule action to HTTP push and configure the instance as follows:

```text
URL: https://<CPOLAR_DOMAIN>/onenet/forward
token: <FORWARD_SHARED_TOKEN>
Message mode: Plaintext
```

The local service logs `url verification passed` when OneNET verification succeeds.

## Starting the Forwarding Service

Open PowerShell in the repository root:

```powershell
$env:FORWARD_SHARED_TOKEN="<FORWARD_SHARED_TOKEN>"
$env:TARGET_DEVICE_NAME="<ONENET_DEVICE_B_NAME>"
$env:EXPECTED_SOURCE_ID="<ONENET_DEVICE_A_NAME>"
$env:ONENET_PRODUCT_ID="<ONENET_PRODUCT_ID>"
python .\firmware\tools\onenet_forward_server.py
```

Without the OneNET API settings, the service runs in dry-run mode and only prints the requests it would send.

Open another terminal to start the tunnel:

```powershell
cpolar http 3000
```

Enter the latest HTTPS domain generated by cpolar in the OneNET HTTP push instance. Free domains may change after a restart.

## Enabling Live Property Delivery

Set the following additional environment variables before starting the forwarding service:

```powershell
$env:ONENET_SET_PROPERTY_URL="https://iot-api.heclouds.com/thingmodel/set-device-property"
$env:ONENET_AUTH_HEADER_NAME="authorization"
$env:ONENET_AUTH_HEADER_VALUE="<ONENET_AUTHORIZATION>"
```

The `authorization` credential includes an expiration time and must be regenerated after it expires. Do not store it in source code, documentation, or Git history.

Device B receives messages on this topic:

```text
$sys/<ONENET_PRODUCT_ID>/<ONENET_DEVICE_B_NAME>/thing/property/set
```

After receiving `source_id=<ONENET_DEVICE_A_NAME>`, Device B updates the corresponding channel using `max_tx_idx` and `max_tx_value`. It disables the output when a reset message is received.

## Verification Procedure

1. Start the Python service and confirm that it is listening at `127.0.0.1:3000/onenet/forward`.
2. Start cpolar and update the OneNET HTTP push URL.
3. Enable the OneNET rule.
4. Start Device B and confirm that MQTT is connected and the property-setting topic is subscribed to.
5. Start Device A and apply an input to the sensor array.
6. Check Device A reports, Python forwarding responses, and Device B channel updates.
7. Remove the input and confirm that Device A sends one reset report and Device B disables the output.

## Troubleshooting

- `401 bad token`: The HTTP instance token does not match `FORWARD_SHARED_TOKEN`.
- GET requests but no POST requests: URL verification succeeded, but the OneNET rule is disabled or its conditions are not met.
- Persistent `DRY-RUN`: `ONENET_SET_PROPERTY_URL` and a valid authorization credential have not been configured.
- Old data arrives unexpectedly: OneNET may retry earlier notifications. The forwarding script uses property timestamps to filter duplicate or stale messages.
- No requests reach cpolar: Confirm that the URL uses the current HTTPS domain and includes `/onenet/forward`.

The local Python and cpolar setup is intended for reproducing experiments and is not recommended as a long-term production deployment.
